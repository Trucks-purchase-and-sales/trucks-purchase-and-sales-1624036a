CONCLUSION
=====================================================================
Phase 2, section 9.1 (audit RLS by hand) is complete. Zero Critical or High
findings. Every sensitive table has real, scoped policies; the only "true"
policies are on intentionally-public reference data; the only zero-policy
table is intentionally fully locked and reachable only via a hardened RPC.

Two minor, non-security items noted for later (see threat-model.md):
1. A handful of policies check only `admin` (not `platform_admin`) where
   most others check both via has_any_role — e.g. profiles_select_self_or_admin,
   user_roles_select_self_or_admin, and the six `future_admin_read` policies.
   This is MORE restrictive, not less, so it is a possible functional gap
   (platform_admin unable to do something admin can) rather than a security
   risk. Worth confirming intent in Phase 3.
2. demand_opportunity_status_history allows a direct client INSERT (unlike
   its sibling history tables) but the WITH CHECK is properly scoped to
   admin/platform_admin/company_management/sales_manager roles or the
   specific demand's assigned sales agent — confirmed correctly scoped, not
   a gap.
