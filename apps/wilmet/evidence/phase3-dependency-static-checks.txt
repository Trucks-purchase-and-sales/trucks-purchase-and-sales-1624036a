npm audit
=====================================================================
1 high-severity finding, no fix available from the maintainer:

  xlsx  *
  Severity: high
  Prototype Pollution in sheetJS - GHSA-4r6h-8v6p-xvw6
  SheetJS Regular Expression Denial of Service (ReDoS) - GHSA-5pgg-2g8v-p4x9
  No fix available

Where it's used: src/lib/document-text.ts, imported dynamically in the
browser (`await import("xlsx")`) to extract text from uploaded
spreadsheet files (.xlsx/.xlsm/.xls/.csv/.ods) as part of the OCR
document-scan feature (src/components/ocr/OcrPrefillDialog.tsx). A
maliciously crafted spreadsheet uploaded through this feature could
freeze or corrupt the browser tab of whoever uploads it.

Blast radius assessment: contained to the browser (this runs
client-side, not server-side), and requires the vulnerable file to be
uploaded through this specific feature by someone with access to it.
Not a server-side or cross-user exposure.

DECISION (Salma, 2026-08-24): accept this risk for now and document it.
Revisit if the xlsx maintainers ship a fix, or if replacing the library
becomes worthwhile for other reasons. If ever addressed, it's an app
code change (swap the parsing library) and should go through Lovable.
